Agentsensus: Consensus-Compressed Shared Memory for
Multi-Agent Story-World Simulation

A shared long-term memory that merges agents’ equivalent memories into multi-witness records and self-organizes into a navigable memory graph.

Scenario 三国演义 (Romance of the Three Kingdoms) Horizon 60 ticks, checkpointed every 20 Agents 191 (33 active) Model gpt-5-mini
Abstract

Multi-agent story-world simulations give every agent a private memory stream, so the same event is stored once per witness, memories of one plotline are scattered across isolated stores, and nothing connects what one agent knows to what another experienced. We present Agentsensus, a story-world simulation framework whose shared long-term memory performs consensus compression: every deposited memory is atomized into self-contained statements, semantically matched against the store, and — when an LLM judge deems two statements equivalent — merged into a single record whose owner-set is the union of its witnesses. Atomized pieces of one compound memory are automatically linked (affiliated), and recall automatically expands one hop along these links, so the memory self-organizes into a graph that retrieval exploits without any agent-side memory management. On a 60-tick simulation of Romance of the Three Kingdoms seeded with memories sedimented from chapters 1–40, and compared under an equal-granularity protocol against three per-agent memory baselines (Generative-Agents-style streams, G-Memory-style hierarchical graph, ACL-based collaborative memory), consensus is the only backend whose simulation memories become shared (19% multi-owner, merges reaching 6 witnesses; baselines 0%) and linked (96% with affiliated edges; baselines 0%), while also writing the fewest entries (717 vs 920–1066). The emergent memory graph tracks the story’s social structure: agents who talk overlap in memory 23× more than those who don’t, linked memories share witnesses at Jaccard 0.75 vs 0.04, and cross-agent memory links run almost exclusively between conversing agents.

1 Introduction

Story-world simulation places dozens of LLM-driven characters into a fictional world and lets a narrative unfold from their interactions. The dominant memory design, inherited from Generative Agents [1], gives each character a private memory stream. This is faithful to individual cognition but structurally wasteful and structurally blind for a shared world: when ten officers attend one war council, ten near-identical records are written; when a courier’s report, the battle it describes, and the order it triggers are recorded by different characters, no store knows these memories belong to one plotline.

Both problems compound with scale. A simulation seeded from a full novel carries thousands of sedimented memories per character; every additional witness multiplies storage; and the connective tissue of the story — who knows what, together with whom — exists nowhere in the memory substrate, only implicitly in the transcript.

Agentsensus takes the opposite starting point: the world’s memory is one shared store, and sharing is computed, not assumed. Memories remain owner-scoped — an agent recalls only what it owns — but when two agents record the same event, the mechanism detects the equivalence and folds the records into one entry owned by both. Two further mechanisms give the store internal structure: pieces split from one compound memory are automatically cross-linked, and recall automatically surfaces linked memories the caller also owns.

A repeated empirical finding shaped the design: agents do not manage memory. Across two models (deepseek-v4-flash, gpt-5-mini) and all four backends, agents issued zero calls to discretionary memory-management actions (linking, unlinking, forgetting, revising) even with documentation, worked examples, and a query-based interface. Every structural property we report therefore comes from mechanisms that run inside remember and recall themselves — the only two memory operations agents actually use.

Contributions.

  • A story-world simulation framework with a deterministic tick-barrier scheduler, passive environments and information carriers, kernel-held conversation threads with distance-delayed delivery, and full-system checkpoints enabling bit-for-bit resumption.
  • A consensus-compressed shared memory: self-contained atomization, semantic-prefilter + LLM-judged equivalence merging with owner-set union, automatic affiliation of split pieces, and auto-expanding owner-scoped recall.
  • An equal-granularity, simulation-only evaluation protocol against three faithful baseline reimplementations, isolating the memory mechanism from confounds of storage granularity and seeded content.
  • A three-layer case-study methodology (interaction graph, memory-affiliation graph, ownership relation) quantifying how the emergent memory structure tracks the story’s social structure.

2 Related Work

Memory for LLM agents.

Generative Agents [1] established the stream-of-memories design — per-agent records scored by recency, importance, and relevance, periodically compressed into reflections — which subsequent agent frameworks largely inherit [8]. MemGPT [4] treats context as a memory hierarchy managed by the LLM itself; Reflexion [5] persists self-feedback across episodes. Closer to our graph mechanisms, HippoRAG [6] indexes a corpus as an entity graph for multi-hop retrieval, and A-MEM [7] links an agent’s notes into an evolving network. These systems structure the memory of one agent or one corpus; Agentsensus structures memory across agents, with ownership as a first-class dimension.

Multi-agent memory.

G-Memory [3] organizes a multi-agent system’s history into a hierarchical insight/query/interaction graph queried at both team and agent level. Collaborative-memory designs [9] share fragments across users under dynamic access control. Both keep per-contributor records intact; neither merges equivalent records across contributors — the core of consensus compression — nor derives the memory graph automatically from deposit-time structure.

Story-world simulation.

BookWorld [2] builds interactive agent societies from novels, with per-character memories extracted from the source text; our sedimentation stage follows the same motivation. Agentsensus differs in making the sedimented and runtime memory a single consensus store, and in evaluating the memory substrate itself (footprint, sharing, graph structure) rather than only the produced narrative.

3 The Agentsensus Framework

3.1  World model and scheduler

A world is a set of characters (LLM-driven), environments, and information carriers (both passive: their responses to act_on/read are computed synchronously by the kernel), placed on a location map with pairwise distances. The kernel advances in ticks with a two-phase barrier: all awake characters decide concurrently against the same pre-tick snapshot of the world, then effects apply sequentially in a fixed order — event order is deterministic and independent of LLM latency. Messages are kernel-held conversation threads: co-located speech delivers next tick, remote messages are delayed by map distance, and delivery (with wake=true) is what wakes a sleeping agent. Full-system snapshots (agent short-term state, kernel runtime, complete memory store with embeddings) are written every 20 ticks; any run resumes bit-for-bit.

3.2  Sedimentation: from novel to memory-grounded world

Before simulation, the source novel (chapters 1–40) is sedimented: events are extracted chapter by chapter, attributed to the characters who witnessed them, and deposited as atomic memories with story-order metadata. Each character’s boundary state — alive or dead, and where — is then derived from its own memory timeline (LLM extraction over the ordered memories, with a canon-knowledge fallback anchored to the boundary chapter); dead characters are archived, living ones are placed at their last grounded location. Each backend ingests the same sedimented events under its own storage rule (§4.2), so every method starts from the world state its own mechanism would have produced.

3.3  Consensus shared memory

The store holds rows of (text, embedding, owner-set, affiliated-set, metadata). Three steps run inside every remember:

  • Self-contained atomization. A compound deposit is split by an LLM into atomic statements, each required to be independently interpretable — pronouns resolved to names, who/what/where carried over. All backends share this exact step (§4.3), so granularity is never a confound.
  • Consensus merge. Each atom is embedded and matched against the store (cosine pre-filter at 0.70 — deliberately permissive, because self-contained phrasings of the same event from different viewpoints embed further apart than near-identical wordings; at the conventional 0.86, zero cross-witness sim memories ever reached candidacy). An LLM judge picks the equivalent candidate or none. On a match, the records merge: owner-sets union, affiliated-sets union, the shorter text is kept. N witnesses of one event cost one row.
  • Auto-affiliation. The atoms split from one deposit are mutually linked. This is how the memory graph is built — not by agents.

Auto-expanding recall. recall(query) retrieves the top-k semantically matching memories owned by the caller, then follows each hit’s affiliated edges one hop and appends the linked memories the caller also owns, marked via_affiliated. The scattered pieces of a plotline surface together in one call; in our runs, 39/39 recalls returned expanded context (1103 linked memories, ≈28 per call).

3.4  Query-addressed memory operations

No memory operation takes a raw id. forget, revise_memory, and the affiliation operations address a memory by a natural-language query, resolved to the caller’s best-matching owned memory; owner-scoping is thereby enforced at resolution. The design responds to a robust behavioral finding: LLM agents never thread opaque ids across turns — in earlier runs every id-based operation had ≈0 uses. Query addressing removes the interface barrier; that agents still do not use discretionary operations (§5.5) is what motivates building all structure into remember/recall instead.

4 Experimental Setup

4.1  Scenario

三国演义 chapters 1–40 are sedimented onto 191 canonical characters (33 active at the boundary, the rest archived as dead; ~6,000 consensus events). All four backends then run the same 60-tick simulation — same scenario file, same action repertoire, same model (gpt-5-mini; embeddings text-embedding-3-small) — in three checkpointed 20-tick stages.

4.2  Baselines

  • Generative-Agents memory [1]: per-agent private streams; insert-time importance scoring; reflection synthesis over high-importance windows.
  • G-Memory [3]: shared store organized as interaction/insight tiers with periodic LLM distillation into insight nodes and bi-level retrieval over provenance edges.
  • Collaborative memory [9]: per-owner fragments guarded by access-control lists; recall is ACL-filtered server-side.

All three ingest the sediment under their own rule (one row per witness) and run their own machinery over it (GA importance+reflections; G-Memory distillation) before tick 0, so each starts from a self-consistent initial state.

4.3  Fairness protocol

Equal granularity. Every backend routes remember through the same atomization code with the same self-containment requirement. Entry counts are therefore directly comparable; the only remaining difference is what each mechanism does with identical atoms.

Simulation-only accounting. All reported numbers cover memories the simulation itself generated (remember/act_on deposits). Sedimented content and baseline by-products (GA reflection nodes, G-Memory distillation nodes) are excluded on all sides.

4.4  Metrics

  • Structure (deterministic): sim-entry count; share of multi-owner entries; share of entries with affiliated edges.
  • Continuation quality (LLM-judged, mean±std over 3 scorings of the full 60-tick transcript): grounding — the fraction of the sim’s own events consistent with the canon; trajectory — agreement of character arcs with reference arcs from held-out chapters 41–60; narrative — judged coherence/drama/fidelity (1–5).
  • Three-layer alignment (§5.3): relations between the interaction graph, the affiliation graph, and the ownership relation.

5 Results

5.1  Footprint and structure

5.4  Structure compounds with horizon

Shared and linked structure is not a transient: across the 20/40/60-tick checkpoints, sim memories grow roughly linearly while shared memories and affiliated edges grow with them — the merge finds more cross-witness events as the story densifies.

5.5  Agents do not manage memory — mechanisms must

Across all four backends and both models tested, agents issued zero calls to every discretionary memory-management action — linking (add/set/remove_affiliated), explicit link-reading (get_affiliated), forgetting, and revision — despite documentation, worked skill examples, and the id-free query interface. In contrast, the two mechanism-embedded operations carried everything: remember (with atomization, merging, auto-affiliation inside) and recall (with auto-expansion inside; 39/39 recalls returned linked context). We take this as a design principle for agent memory systems: structure must be a side-effect of the operations agents already perform, not a task delegated to them.

6 Discussion and Limitations

What consensus buys. Under equal granularity and sim-only accounting, consensus dominates structurally — fewest entries, all sharing, all graph structure — and this no longer trades against judged quality (best narrative, competitive elsewhere). The three-layer alignment argues the structure is meaningful: it recovers the story’s social organization from the memory substrate alone.

Limitations. (i) Quality metrics are LLM-judged and noisy; we report 3-scoring means with std, but ranking claims beyond narrative should be treated cautiously. (ii) Results cover one scenario (三国) and one 60-tick horizon; the protocol ports directly to other sedimented worlds and longer runs (checkpoints exist), but those runs remain future work. (iii) Auto-expansion is deliberately uncapped, appending ≈28 linked memories per recall; this enriches context but grows prompts, and its cost–benefit curve is unmeasured. (iv) The equivalence judge and atomizer consume extra LLM calls per deposit — the price of compression is paid at write time. (v) One baseline artifact: G-Memory re-runs distillation on resume (its distill bookkeeping is not check-pointed); sim-only accounting excludes distillation nodes, so reported numbers are unaffected.

7 Conclusion

Agentsensus treats a story world’s memory as a single consensus store: equivalent memories merge across witnesses, split memories link into a graph, and recall walks that graph automatically. On a novel-seeded 60-tick simulation, this yields the smallest memory footprint at equal granularity, the only shared and linked memory structure among four backends, and an emergent memory graph that mirrors the story’s social structure — at no cost to judged narrative quality. The broader lesson is that memory structure in multi-agent systems must be mechanized, not delegated: agents reliably use only remember and recall, so that is where the structure has to live.
